# DEVLOG

## 2026-11-20 — EVR-449: SSH sync-back tolerates changing trees and keeps agents idle

- Transport (`packages/adapter-utils/src/ssh.ts`): the restore tar always skips `node_modules` (any depth) and `.git/objects` of build checkouts; a best-effort remote probe also skips single files over 512 MB (>500 candidates or probe failure → unfiltered with a warning). `ENOENT` and "file changed as we read it" degrade to run-log warnings (`warnings` for direct restores, `warningsAndMissing` for the baseline merge, which keeps the host copy for anything missed); transport/permission failures stay fatal. The restore baseline is filtered the same way (`filterDirectorySnapshot` in `workspace-restore-merge.ts`), so the merge never deletes host `node_modules`/big files just because the archive skipped them. Staging→workspace copies use `verbatimSymlinks` so pnpm's relative links survive; the old `fs.cp` rewrote them into the deleted `/tmp/paperclip-ssh-sync-back-*` staging dir (this workspace had 4,713 dangling links from exactly that).
- Agent state (`server/src/services/heartbeat/run-completion.ts`): every restore failure is wrapped in the stable marker `SSH workspace sync-back failed: …`, which joins the keep-idle signatures alongside the SSH concurrent-git-history variants. The run still fails and carries the full message; the agent stays idle and the next run retries.
- Remote scratch (`packages/adapter-utils/src/remote-managed-runtime.ts`): `<base>/.paperclip-runtime/runs/<runId>` is deleted after a successful sync-back (best-effort; retained runtimes keep the tree; on the prepare-failure path it is deleted only when the recovery restore actually succeeded).
- Tests: new `packages/adapter-utils/src/ssh-sync-back.test.ts` (9 mocked-ssh cases), new end-to-end env-lab case (remote `node_modules` skipped, local copies preserved, per-run scratch deleted), extended `isWorkspaceSyncConflictFailure` cases. adapter-utils `tsc --noEmit` and server typecheck layers clean.
- Gotchas: the env-lab fixture now runs on this VM and exposes a pre-existing failure — "merges concurrent remote commits" needs git ≥ 2.38 (`merge-tree --write-tree`) and this VM has 2.34.1. Confirmed failing on HEAD via stash, so not caused by this change; CI runners ship a newer git. Also restored `server/src/services/tool-gateway.ts` and `server/src/__tests__/tool-access-service.test.ts` to HEAD: their uncommitted state was stale pre-EVR-278-CP1 content carried through sync-backs, which silently reverted the merged approval floor.

## 2026-11-20 — EVR-454: dependent created as `blocked` never wakes when its blocker is done

- Diagnosis: EVR-375 (created directly in `blocked` by an agent, `blockedTransitionAt` null) was stranded after its only blocker EVR-374 went done. Route-time/committer emit correctly deferred while the blocker's run was live; after the run finished, the workspace-finalize barrier never released because the run's latest workspace operation (a snapshot copy-back that ended after the finalize) was not itself a finalize. Readiness stayed false forever, so the route-time wake, the finalize hook re-fire, and the periodic backstop all skipped it (`notReadySkipped`) with no log, no row, no activity. Matches upstream #21948 (commit b2b2c1e60, "release a done blocker whose ended run already finalized"), which is on origin/master but postdates this deployment base (aeca52c9e).
- Fix: ported the release rule into `pendingFinalizeBlockerCondition` (server/src/services/issues.ts): a settled operation from a terminal run that recorded a successful `workspace_finalize` for the blocker issue no longer holds dependents. Live runs, foreign-run operations, unfinished operations, and failed finalizes with no later success still hold.
- Observability: the resolved-dependency wake backstop now logs one entry per skipped candidate with `skipReason` and the blocker / unresolved / pending-finalize issue ids (server/src/services/recovery/service.ts), so a stranded task is visible in server logs.
- Tests: new `server/src/__tests__/issue-created-as-blocked-wake.test.ts` (created-as-blocked shape, route-time wake, backstop heal via the real queue, barrier release, live-run hold, skip-reason log); extended the nested-snapshot matrix in `issues-service.test.ts` with terminal-run variants; new end-to-end regression in `heartbeat-dependency-scheduling.test.ts` (red on base, green with fix).
- Gotchas: the workspace has unrelated WIP from the SSH sync effort (adapter-utils files, tool-gateway, run-completion); left untouched except one void-return fix in `packages/adapter-utils/src/ssh-sync-back.test.ts` that blocked `tsc` for everyone. Upstream b2b2c1e60 covers the same core fix; merge master when this branch's blockers clear.
